Git vs. GitHub: ¿Cuál es la diferencia?

Git

El motor interno que lleva el registro completo.

  • Es un software (herramienta) de la línea de comandos.
  • Se ejecuta localmente en la computadora de cada desarrollador.
  • Lleva el historial y control de versiones de los archivos.
  • No requiere internet para registrar instantáneas de trabajo.

GitHub

La central de colaboración en la web.

  • Es un servicio privado de alojamiento en la nube.
  • Permite que varios desarrolladores sincronicen su trabajo (requiere internet).
  • Brinda herramientas para revisar código, manejar permisos y gobernanza.
  • Actúa como la "copia maestra" segura del código de la empresa.

1. Funcionalidades de Auditoría y Trazabilidad

Commits (Instantáneas)

Son puntos de guardado inmutables. Cada vez que se guarda un cambio, Git registra los archivos modificados junto con el autor, la fecha y un mensaje descriptivo del porqué.

Git Blame / Historial

Una herramienta de auditoría línea por línea. Permite hacer clic en cualquier parte del código y ver exactamente qué desarrollador la escribió y en qué momento preciso.

Git Revert (Rollbacks)

Si un commit introduce un error, esta función crea un "anti-cambio" automático que deshace el error sin alterar ni borrar el historial de lo que pasó, manteniendo la seguridad.

Caso Práctico: Un Error Crítico en Producción

Escenario: Se lanza una actualización importante y, de repente, una funcionalidad clave deja de funcionar.

Sin GitHub

El equipo entra en pánico.

  • Revisamos manualmente cientos de archivos intentando adivinar quién tocó qué.
  • Tratamos de deshacer los cambios "de memoria", corriendo el riesgo de romper otras cosas.
  • Horas de inactividad afectando a los usuarios y al negocio.

Con GitHub

Mantenemos el control absoluto.

  • Entramos al historial y vemos exactamente qué archivo se modificó hace dos horas.
  • Con un solo clic presionamos "Revertir".
  • El sistema vuelve a la versión estable anterior en segundos.
  • Investigamos el error con calma sin afectar a los usuarios.

2. Funcionalidades de Aislamiento y Paralelismo

Ramas (Branches)

Crean entornos de trabajo paralelos. Puedes clonar el proyecto principal (rama main), experimentar, romper cosas y crear nuevas funciones sin que el producto en vivo sufra daños.

Git Merge

La capacidad de unir dos ramas. Cuando un equipo termina su trabajo en una rama aislada, Git combina inteligentemente ese código nuevo con el proyecto principal de forma segura.

Resolución de Conflictos

Si dos personas editan exactamente la misma línea, GitHub no sobrescribe los archivos al azar. Detiene el proceso y muestra una interfaz visual para decidir qué versión conservar.

Caso Práctico: Trabajo Paralelo

Escenario: Un equipo necesita corregir un error urgente, mientras otro desarrolla una nueva funcionalidad al mismo tiempo.

Sin GitHub

Se generan cuellos de botella.

  • Tienen que turnarse para trabajar en el código.
  • Se envían archivos por correo o carpetas compartidas (.zip).
  • El riesgo de sobrescribir accidentalmente el avance del compañero al guardar en el servidor central es altísimo.

Con GitHub

Logramos desarrollo concurrente.

  • El producto principal (el tronco) está intacto y seguro.
  • El equipo 1 crea su propia rama aislada para corregir el error.
  • El equipo 2 crea su rama para la nueva funcionalidad.
  • Ambos trabajan al mismo tiempo, equivocándose y probando cosas sin que el proyecto central sufra daño.

3. Funcionalidades de Control de Calidad

Pull Requests (PRs)

Son peticiones formales para integrar código. Crean un espacio dedicado donde el equipo puede ver un resumen visual ("diff") de todo lo que se añadió o eliminó antes de aceptarlo.

Code Review (Revisión)

Dentro de un PR, los compañeros pueden dejar comentarios directamente sobre líneas de código específicas, sugiriendo mejoras de seguridad o de rendimiento antes de aprobar.

Protección de Ramas

Reglas estrictas configurables. Por ejemplo: "Ningún código puede ir a producción sin ser aprobado por al menos 2 desarrolladores senior y pasar todas las pruebas automáticas".

Caso Práctico: La "Aduana" del Código

Escenario: Un desarrollador termina una nueva funcionalidad y necesita integrarla al código principal de la empresa.

Sin GitHub

Publicación a ciegas.

  • El desarrollador simplemente copia y pega sus archivos en la carpeta principal de producción.
  • Si hay un error oculto o una vulnerabilidad de seguridad, acaba de dañar todo el proyecto para los clientes.

Con GitHub

Calidad garantizada y auditada.

  • El desarrollador levanta la mano y dice: "Terminé, solicito integrar mi trabajo" (Pull Request).
  • El sistema bloquea la integración automáticamente.
  • Otro miembro revisa el código línea por línea, deja comentarios y finalmente aprueba con su usuario.

Planes Individuales: Free vs. Pro

GitHub Free

Todo lo básico para arrancar sin costo.

  • Almacenamiento (Storage): 500 MB de paquetes de GitHub limitados.
  • Acción GitHub (CI/CD): 2,000 minutos/mes gratis para automatizar tareas.
  • Codespaces: 120 horas core/mes gratuitas en servidores virtuales limitados.
  • Soporte: Solo acceso al soporte básico y la comunidad.
  • Sin protección de ramas en repositorios privados.

GitHub Pro

Superpoderes para desarrolladores avanzados ($4/mes).

  • Almacenamiento (Storage): 2 GB de paquetes de GitHub.
  • Acción GitHub (CI/CD): 3,000 minutos/mes para builds más largos/frecuentes.
  • Codespaces: 180 horas core/mes con servidores virtuales más potentes.
  • Soporte: Acceso directo vía email con SLA básico.
  • Protección estricta de ramas incluso en repos privados.
  • Wiki y GitHub Pages en repositorios privados.

Colaboración a Escala: GitHub Organizations

Gestión de Equipos

Agrupa a los desarrolladores en equipos (ej. Frontend, QA) y asigna permisos detallados (lectura, escritura, administración) por repositorio de forma estructurada.

Seguridad y Auditoría

Fuerza políticas estandarizadas de seguridad: exige Autenticación en Dos Pasos (2FA) obligatoria y visualiza los registros de actividad de todos los miembros.

Planes y Facturación

Unifica la facturación. Planes como GitHub Team o Enterprise proveen integraciones avanzadas (SAML SSO), más recursos y soporte prioritario.
